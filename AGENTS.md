# Aspirations contributor instructions

Read `docs/design.md`, `docs/repository.md`, [the knowledge index](docs/knowledge/README.md), relevant topic notes, `src/core/SPEC.md` and the affected family's `SPEC.md` before editing. Update the owning living contract and `tests/scenarios.md` in the same gameplay change. Use [the shared story acceptance guide](docs/story-authoring.md) for origin/target, lifecycle, terminal/cancel, stale actions, visible state and registered regression coverage; preserve documented family exceptions. Historical review indexes and execution plans are not competing contracts.

Use English for all authored prose, identifiers, comments, tool output, metadata and localization. Only `localization/english/*_l_english.yml` is supported; preserve its UTF-8 BOM and native header. Do not use generic YAML formatters on CK3 localization. PowerShell/Markdown use UTF-8 and LF. No formatter is configured; use syntax checks and inspect diffs.

Before writing or editing player-facing text, read [the writing guide](docs/player-facing-writing.md) and its [native references](docs/knowledge/narrative-presentation.md). Event and decision prose, selection tooltips and option flavor describe the character's motives and actions in roleplay. Put consequences in native Will Happen or Has Happened effect sections; keep exact objectives and progress on Story cards. Verify the separation in the actual game, not only in localization files.

Author ordinary CK3 files in story-owned `game/` folders. Core owns lifecycle and cross-story coordination; stories cannot mutate each other's private state. No transpiler, runtime framework, dependency additions, custom GUI replacements or undocumented identifier changes. Create only categories that are used. Reserve stable event IDs in the owning SPEC before implementation and never repurpose saved IDs.

Use installed PowerShell 7, .NET and Git. Prefer `rg`. Preserve existing user edits; no push, PR, publication, game-install modification, Workshop-source modification or active-playset mutation without explicit authorization. Never redistribute extracted game/Workshop assets or commit secrets, saves, profiles, screenshots, runtime logs, local paths, `.build/`, `.local/`, `dist/` or `.superpowers/`.

Test tooling changes first with `pwsh -NoProfile -File tools/tests/run.ps1`, then dev/release build/check commands. No additional test framework is needed. Static checks cannot establish game semantics. Gameplay requires disposable campaign scenarios, measured deltas, fresh logs and screenshots; report unverified cases honestly. Consult the relevant knowledge topic before relying on construction attribution/reservation/token ownership, knowledge/disclosure, calendar/lifecycle, Story scope/localization or profile/automation/DPI capabilities. Static evidence indexes and unit tests never certify native rendering or gameplay.

Close the test CK3 process before rebuilding dev output. Resolve user data from actual OS Documents configuration and require the explicit user-data path for registration. Keep machine setup and transient findings in `.local/MODLOG.md`; update validated reusable discoveries in `docs/knowledge/` in the same change, with status, CK3 version, observation, tracked source or reproducible test, implication and limits. Link portable tracked scenarios/fixtures; ignored historical reports cannot be the only evidence. If no durable finding was made, state "No new durable finding" in the change/report instead of inventing a note. `docs/modding-notes.md` remains a navigation entry point.

Commit only authored changes with short imperative English messages. No public license has been selected; document licensing before public release.
